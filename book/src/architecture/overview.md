# 总览：一个引擎，四个外壳

```text
 桌面版             手机版                 aa4c              扫码收发页        插件命令
 (Rust UI)    (Kotlin / Swift 薄壳)   (CLI · MCP · 中转站)   (纯 HTML)       (Wasm 沙箱)
     \               | UniFFI                |                  |               /
      +--------------+-----------------------+------------------+--------------+
                                             |
                  aa4c-engine：命令注册表 + CallerContext + 事件流 + 能力检查
                                             |
           send / space / share / contacts  ←  net（QUIC · 信标 · 连接阶梯 · 中转站）
                                             |
                    id（个人/设备密钥 · 证书 · 吊销）     state（redb + config.toml）
```

## 引擎

全部业务逻辑在一个 Rust 引擎里：身份、发现、连接、发送、同步、分享、中转、插件宿主。引擎对外只有两样东西：

- **命令**：有 id、参数/结果 JSON Schema、能力级别和副作用描述的操作。界面上的每一个动作都是一个命令。
- **事件**：引擎主动推送的变化（设备上下线、发送进度、收到请求、空间成员变更……）。

每次调用都附带由入口创建、调用者不能自行扩大权限的 `CallerContext`：来源、允许的能力级别、文件读写根目录、
是否有人在场、截止时间。命令分发器在唯一入口做参数、能力和资源授权；命令实现不能因为“来自本机”就绕过它。

详见[命令与事件](commands.md)。

## 四个外壳

| 外壳 | 引擎在哪里运行 | 说明 |
|---|---|---|
| 桌面版 | 桌面进程内 | 同时开一个本地 IPC 通道，让 `aa4c` 命令行和 AI agent 能操作正在运行的桌面版 |
| 手机版 | App 进程内（Android 用前台服务承载）| 经 UniFFI 生成的 Kotlin/Swift 绑定调用命令、订阅事件 |
| `aa4c` | 常驻进程（`aa4c up`）| 无界面；同一个程序也是命令行客户端、中转站、MCP 服务 |
| 扫码收发页 | 不运行引擎 | 引擎临时提供的 HTML 页面，浏览器访问 |

## 平台能力适配

Wi-Fi Direct、Wi-Fi Aware、临时热点、系统蓝牙/红外发送不是第二套业务引擎。Android、iOS 和桌面外壳只向引擎报告
“当前有什么能力、需要哪些人类步骤”，并执行引擎批准的 `prepare / cancel` 计划；文件授权、大小预算、路径净化、路径选择状态机和结果事件仍在 Rust。

建立出本地 IP 后复用 `aa4c-net` 的 QUIC 或扫码收发 HTTP；操作系统自己接管文件交付时，AA4C 只报告系统能证明的状态。
适配器不可用不会影响基础传输，也不能为了方便绕过命令注册表。详见[近场交付](../network/proximity.md)。

同一个数据目录只允许一个引擎实例（锁文件）。命令行在有引擎运行时经 IPC 调它；没有时，只读命令可以进程内直接执行，
需要网络常驻的命令提示先 `aa4c up`。IPC 传的是命令与调用来源，不传“我是管理员”一类可伪造的权限位；
权限由服务端依据本地入口配置生成。

## 与 photocraft 的同与不同

AA4C 借鉴了 [storytold/photocraft](https://github.com/storytold/photocraft) 的「一切皆命令、薄界面、分层强制、永不崩溃」。
关键不同：photocraft 是「打开文件 → 跑命令 → 保存」的一次性作业；AA4C 必须**常驻**——要一直监听、发信标、维持同步、向中转站登记。
所以 AA4C 是「常驻引擎 + 多个客户端」，与 tailscaled/tailscale、Syncthing 同构。

## 本地 IPC

- Unix：数据目录下的 Unix domain socket，权限 0600；Windows：命名管道，ACL 只允许当前用户。
- 协议：JSON lines，`{"id":1,"command":"send.files","params":{…}}` → `{"id":1,"result":{…}}` 或 `{"id":1,"error":{…}}`；
  订阅事件：`{"id":2,"subscribe":"events"}` 后持续收到事件行。
- 单条消息与连接数有上限；IPC 只对本机当前用户开放，不监听任何网络端口。
