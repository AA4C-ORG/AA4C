# 线路协议

设备与设备之间说的话。扫码收发页面向浏览器，走 HTTP，不在本章（见[扫码收发页](../surfaces/web-drop.md)）。

## 传输层

- **只用 QUIC**（quinn），局域网与跨网相同（[ADR 0004](../../../docs/adr/0004-quic-only.md)）。ALPN：`aa4c/1`。
- **认证**：TLS 1.3 双向认证，双方出示**原始公钥**（RFC 7250）——即各自的设备公钥，不用 X.509 证书
  （[ADR 0005](../../../docs/adr/0005-raw-public-keys.md)，待 M0 实验证实）。握手时必须把对方公钥绑定到一个已认证来源：
  默认信标解出的连接卡片、临时「所有人」模式的签名卡片、二维码、邀请/一次性发送链接，或已缓存的有效设备证书。
  拨号方必须在握手时验证被拨设备，不能「先接受任意服务端公钥，握手后再说」。监听方只在两种情况下接受未知来电设备的原始公钥：
  ① 来电来自本地 IP 链路，且我处于「所有人」模式；② 本机有未过期的邀请口令或一次性发送口令（可以跨网络）。
  这类连接在 Hello 的设备证书验证和关系判定完成前只当 Stranger，不给任何已有关系的权限；情况 ② 的连接只允许出示口令
  （`contact.invite` / `share.redeem`），口令不对立即断开。远程来电在「所有人」模式下也不被接受。
- 保活：QUIC keep-alive 与空闲超时，空闲超时须明显长于任何应用层等待（第一代的教训：8 秒空闲超时曾在共享 CI 机器上误杀连接）。

## 帧与消息

- 每个 QUIC 双向流的开头是**控制消息**：4 字节大端长度 + UTF-8 JSON，单条上限 1 MiB（[ADR 0007](../../../docs/adr/0007-json-control-messages.md)）。
- 文件内容是控制消息之后的**裸字节**，长度由前面的控制消息声明。
- 新增字段一律有默认值或可选，未知字段忽略；未知消息类型回 `{"type":"error","code":"unsupported"}`。

### 连接建立后的第一条消息：Hello

```json
{
  "type": "hello",
  "proto": 1,
  "features": ["resume", "space-sync"],
  "device_cert": { "...": "个人密钥签名的设备证书" },
  "revocations_digest": "…"
}
```

双方交换 Hello 后：验证对方设备证书 → 判定关系（我的设备 / 联系人 / 空间成员 / 陌生人）。只有我的设备、联系人与同一空间的成员
之间才继续：吊销列表摘要不同就交换吊销，并用 `addr.update` 互告当前全部地址。陌生人和凭口令进来的连接拿不到对方的其他地址。

### 主要消息（v1）

| 消息 | 方向 | 用途 |
|---|---|---|
| `send.offer` / `send.answer` | 发 → 收 / 收 → 发 | 发送请求（条目列表、文字内联）与接受/拒绝，含每个文件的续传起点 |
| `file.begin` / `file.end` | 发 → 收 | 文件开始（相对路径、大小、起始偏移）与结束（整文件 BLAKE3）|
| `file.ack` | 收 → 发 | 单文件校验结果；失败可重传（上限 2 次）|
| `send.done` | 发 → 收 | 全部完成；**发出后先半关闭写端、等对方关闭再丢弃连接**（第一代教训）|
| `cancel` | 双向 | 明确取消（接收方据此清理未完成文件）|
| `peers.sync` | 双向 | 我的设备之间：联系人、空间、吊销、设置、开放的服务的增量同步 |
| `space.index` / `space.fetch` | 双向 | 共享文件夹的元数据索引交换与按需取回 |
| `contact.invite` | 双向 | 邀请链接的口令出示与确认 |
| `share.redeem` | 收 → 发 | 一次性发送链接的口令出示；通过后发送方发 `send.offer` |
| `tunnel.open` / `tunnel.ok` | 发起 → 目标 / 目标 → 发起 | 远程访问：指明服务名，确认后这条流上是双向裸字节（[远程访问](remote-access.md)）|
| `addr.update` | 双向 | 我的设备、联系人、同空间成员之间互告当前地址（`{"addr":"[2408:…]:41234","kind":"public_v6","observed_at":…}`）|
| `relay.*` | 设备 ↔ 中转站 | 登记地址、查询地址、打洞协调、转发 |

每个文件一条独立的 QUIC 流，多个文件并行，互不阻塞。

## 续传

- 未完成的文件以 `.aa4c-part` 落盘；重连后接收方在 `send.answer` 里报告每个文件已校验的字节数（按 4 MiB 边界截断），
  发送方从该偏移继续发送，并重新流式计算整文件哈希。
- 只有**明确取消**才清理 `.aa4c-part`；网络中断保留以供续传。

## 安全要点

- 接收方强制净化相对路径：拒绝 `..`、绝对路径、Windows 盘符与设备名、路径分隔符变体、控制字符。
- 一切长度、计数、偏移来自网络，都按敌意输入处理：检查上限、用 checked 运算、按声明长度限制内存分配。
- 协议解码器与路径净化纳入 fuzz 测试。
