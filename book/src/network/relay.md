# 中转站的数据边界

中转站由任意常开 AA4C 设备打开开关后提供，负责汇合、打洞协调和最后一档转发。部署与谁能使用见
[连接阶梯](ladder.md)；本章只规定一个不能模糊的边界：**中转站不终止设备之间的端到端 QUIC**。

## 两个平面

```text
设备 A ──控制连接──▶ 中转站 ◀──控制连接── 设备 B
   ╰════════════ 端到端 QUIC 数据报（中转站只按 circuit 转发）════════════╯
```

**控制面**：设备向中转站出示设备证书，登记当前地址、查询对端、申请临时 circuit、协调双方同时打洞、续租与释放。
中转站在这里执行“我的设备 / 被允许的联系人 / 被允许的空间成员”策略与带宽、并发、时长限额。

**数据面**：打洞失败后，中转站为一对已授权设备建立短期 circuit，只转发带 circuit id 的不可靠 UDP 数据报。
设备 A 与 B 的 QUIC/TLS 会话仍由两端终止；中转站看不到 QUIC 流、控制消息、文件名或内容。

不能把内层 QUIC 字节流塞进一个可靠的外层 QUIC stream：丢包时两层重传与拥塞控制会互相放大。若控制连接复用 QUIC，
数据面只能用 QUIC DATAGRAM 或等价的不可靠转发；M4 实验后再固定线格式。

## 授权

1. 中转站先验证来电设备公钥与设备证书，检查吊销。
2. 默认只接受由同一 Person 签发的“我的设备”。
3. 社交中转开启后，按明确的人或空间策略授权；名字、来源地址或 circuit id 都不是身份。
4. A 申请连 B 时，B 也必须在线登记且双方都满足策略；不能只凭 A 声称“B 是联系人”。
5. circuit id 随机、短期、绑定双方设备与方向；过期或任一方吊销后立即失效。

社交中转是 `trust` 设置。插件、MCP act 命令与 `config.toml` 都不能替人扩大授权。

## 中转站能看到什么

能看到：两端设备身份、来源地址、连接时间、数据报大小/数量、总字节数。看不到：文件内容、文件名、目录结构、端到端控制消息。
这些元数据限制必须出现在开启社交中转的界面里，不能只写“完全看不到”。

日志默认只保留聚合用量与错误码，不记录逐包数据、完整公钥或 circuit id；详细诊断需用户临时打开并自动到期。

## 资源与滥用上限

- 每人、每设备、每来源地址的并发 circuit 与新建速率上限；
- 单 circuit 空闲超时、最长寿命和最大累计字节；
- 我的设备与社交中转分别限速，社交流量不能挤死本机连接；
- 数据报大小与队列长度有上限，拥塞时丢包而不是无限缓存；
- 中转站不落盘保存数据报，不提供离线消息或文件存储。

## M4 必须证明

- 对称 NAT 下直连失败后，两台真机能经 circuit 完成同一条端到端 QUIC 会话；
- 中转站抓包只能看到密文数据报，不能解码 AA4C 控制消息；
- 未授权、已吊销、过期 circuit、伪造目标、重放与超限全部被拒绝；
- 丢包与拥塞不会造成可靠传输套可靠传输的灾难性退化；
- 中转站进程重启只让连接重拨，不产生错误的“传输成功”。

封 UDP 网络的 TCP 回退仍是[待细化问题](../open-questions.md)，不能在这个设计里偷偷加第二套传输协议。
