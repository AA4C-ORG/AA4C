# 连接阶梯与中转站

> 决定见 [ADR 0004](../../../docs/adr/0004-quic-only.md)（只用 QUIC）与
> [ADR 0010](../../../docs/adr/0010-self-hosted-relays-only.md)（只用自建中转站）。

## 远程连接要解决两件事

1. **找到对方**：对方此刻的地址是什么？家庭宽带的地址会变，手机会在 WiFi 与 4G/5G 之间切换。
2. **连上对方**：知道地址了，能不能穿过双方的路由器和运营商网络直接连上？

第一代把注意力放在第 2 件事上。第 1 件事同样关键，而且**在没有任何常开设备时最难**——这一点必须如实写清楚。

## 找到对方：地址从哪来

| 来源 | 说明 | 需要什么 |
|---|---|---|
| 信标 | 同一本地 IP 链路，直接发现 | 无 |
| 上次已知地址 | 我的设备、联系人、同空间成员之间每次连上，交换各自当前的所有地址（局域网、公网 IPv6、公网 IPv4、端口映射地址）并缓存；陌生人和链接持有人拿不到 | 之前连上过一次 |
| 我的设备转告 | 我的设备之间同步自己知道的地址；不让联系人转告第三人的地址 | 有另一台自己的在线设备 |
| 中转站（汇合）| 设备定时向中转站登记当前地址；别人连我时先问中转站 | 一台常开设备当中转站 |
| 邀请链接 / 二维码 | 载荷里带着当时的地址与中转站 | — |

**没有任何中转站时**：远程连接只能靠「上次已知地址」。家宽公网 IPv6 前缀通常能保持数天，所以近期连过的设备往往还能直接连上；
但地址一变（路由器重启、运营商重新分配、手机换网）就找不到了，直到双方再次在本地 IP 链路相遇或经邀请链接重新交换地址。
这是「只用自建中转站」的真实代价，界面上要讲清楚，并引导用户把一台常开设备设为中转站。

## 连上对方：阶梯的每一档

拿到对方的候选地址后，**并发**尝试（不是串行），取最先成功的，优先级从高到低：

| 档位 | 界面上叫 | 条件 |
|---|---|---|
| **Lan** | 本地直连 | 同一局域网，或已建立 Wi-Fi Direct / Wi-Fi Aware / 临时热点链路 |
| **PublicV6** | 公网直连（IPv6）| 双方或被连方有公网 IPv6，防火墙放行（国内家宽普遍有公网 IPv6）|
| **PublicV4** | 公网直连 | 被连方有公网 IPv4 |
| **PortMapped** | 公网直连（路由器转发）| 被连方路由器支持 UPnP 端口映射且已打开 |
| **Punched** | 打洞 | 双方都在 NAT 后，借中转站交换地址并同时发包；对称 NAT 时通常失败 |
| **Relayed** | 经中转站（较慢）| 以上都失败；有一台双方都能用的中转站 |

- 每次连接成功后记录档位，[设备页](../surfaces/desktop.md)显示「已连接 · 本地直连」「已连接 · 经中转站（较慢）」。
- 已连接时，若后台发现更高档位可用（例如回到家进入同一本地 IP 链路），引擎另建直连并在应用层把后续文件/续传切过去。
  QUIC 连接迁移能处理同一连接的本地地址变化，但不能凭空把「经中转封装的连接」变成另一条直连；不要把二者混为一谈。
- 端口映射有两道闸：「允许远程连接」开着，且「自动在路由器上开端口」开着；退出时拆除映射。

## 中转站

中转站是**任何一台常开的 AA4C 设备**打开一个开关：桌面版的设置里，或无界面的 `aa4c relay enable`。没有单独的服务器程序。
控制面与数据面的密码学边界见[中转站的数据边界](relay.md)：中转站不终止两端的 QUIC，只转发有上限的不可靠数据报。

- **为谁服务**：默认只为**我的设备**（自动：我的设备通过同步得知我有哪些中转站，不用手填地址）。
- **社交中转**（默认关）：可以按人（某些联系人）或按空间（某个空间的全体成员）开放。开放后，这些人的设备会从联系人信息里
  得知「可以经这台中转站找到你/连到你」。
- **链接担保**：我创建邀请链接或一次性发送链接时，我的设备在自己的中转站登记一张一次性许可；持链接的设备只能凭它连到
  我的这台设备（含打洞协调），用过、到期或撤销即失效。它不是社交中转，也不能用来连别人（[中转站的数据边界](relay.md)）。
- **它做什么**：登记设备的当前地址（汇合）、协调打洞、在必要时转发流量。
- **它看不到什么**：转发的是端到端加密的 QUIC 数据，中转站看不到内容、文件名、目录结构。它能看到：谁的设备在什么时候、
  从哪个地址连过来，转发了多少字节。
- **限额**：带宽与并发连接可设上限；社交中转可单独限额，防止被联系人的大流量拖垮家庭网络。
- **可达性**：中转站自己必须能被外面连上——有公网 IPv6、公网 IPv4（或端口映射成功）。界面上用检测结果说明当前状态，
  只能在局域网内被访问时明确告诉用户「它暂时帮不了外面的设备」，并给出可选的解决办法（配 DDNS、路由器放行端口）。

## 连不上时

按以下顺序判断并告诉用户（[体验原则](../product/experience.md)第 4 条）：

| 情况 | 告诉用户 | 建议 |
|---|---|---|
| 对方不在线（所有地址都无响应，中转站也说不在）| 「张三的设备现在都不在线」| 「他上线后自动发送」；一次性链接也要求发送设备在线，不能假装是云端副本 |
| 不知道对方现在在哪（没有中转站、旧地址失效）| 「找不到张三现在在哪个网络」| 让任一方开中转站；当面或用邀请链接重新连一次 |
| 双方都在运营商共享网络后，打洞失败，无可用中转站 | 「你们俩都在运营商的共享网络后面，没法直接连上」| 让任一方在常开设备上打开中转站，或请共同的联系人开放社交中转 |
| 对方拒绝 / 对方接收模式关闭 | 如实说明 | — |

## 测试

- 进程内**多人多设备测试台**：一个进程里起「我（3 台）+ 爸妈（2 台）+ 同事（1 台）」，走真实 QUIC。
- **netsim**：在测试台上模拟「不在同一网络」：屏蔽直连路径、模拟对称 NAT、UDP 黑洞、丢包、地址变化，验证每一档的选择与降级，
  以及「无中转站时给出正确的失败原因」「有社交中转时必须成功」。
- CI 的 Linux 环境可用网络命名空间构造更真实的 NAT 拓扑。
- 真机验证清单（沿用第一代按「单机 → 同一局域网 → 不同网络」分组的做法）放在 M4。
