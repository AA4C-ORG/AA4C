# 附近：发现与一次性发送

## 信标

> 默认信标的隐私协议与帧格式见 [ADR 0015](../../../docs/adr/0015-private-nearby-discovery.md)（M0 实验已通过）。

每台设备在每个可用本地 IP 接口上定时发出发现数据报（IPv4 组播 + IPv6 链路本地组播）。接口可以来自共同局域网，
也可以来自已建立的 Wi-Fi Direct / Wi-Fi Aware 链路；建链与免安装路径见[近场交付](proximity.md)。不用 mDNS 的理由是我们需要
统一控制多接口 socket、帧上限、隐私模式、重放窗口与进程内测试；mDNS 的 TXT 记录模型不是这里需要的协议接缝。

所有模式共有的明文字段只有：协议版本、时间窗口和随机数。加密条目区按固定档位填充（不足用随机条目补齐，每个周期发出的数据报数
也按档位），旁观者只能看到档位，看不到真实联系人数。包大小、条目数、发送频率与解析成本都有硬上限。

### 隐私：接收模式决定条目

- **仅联系人（默认）**：为联系人发现密钥生成短期发现标签，并加密「设备公钥、端口、设备证书摘要、展示信息」这张最小连接卡片。
  陌生人看不到名字、公钥或公开可验证的签名，也不能用稳定字段跨轮换周期跟踪设备。
- **关闭**：只生成「我的设备」发现密钥能解开的条目。
- **所有人**：用户显式打开、最长 10 分钟。另在本地 IP 链路上发送带设备公钥和签名的公开连接卡片，附近任何人都能看到名字与平台。

隐私目标的边界：信标载荷不能暴露「这是谁」，也不能让同一台设备在不同网络、不同轮换周期之间被关联起来。同一个网络里，
IP 与 MAC 地址本身就能把一台设备的多个包连起来，这不是信标能解决的，也不作为 M0 的通过标准。

帧格式：每个数据报固定 1121 字节，头（版本、30 秒时间窗口、24 字节随机数）加 13 个槽，每槽“标签 + XChaCha20-Poly1305 加密的连接卡片”，
没有联系人的槽填随机字节并打乱位置。每个周期的数据报数取 1 / 2 / 4 / 8 / 16 档，最多容纳 208 个条目，更多的联系人按游标轮转。
接收方接受当前时间窗口及前后各一个，已解开的数据报按随机数去重。没有稳定明文标识（包括真实条目数），解密失败不泄露联系人是否存在，
删除联系人后不再为其生成条目。参数与测量结果见 ADR 0015。

## 附近列表

| 显示为 | 条件 |
|---|---|
| 我的设备 | 证书由我的个人密钥签发 |
| 联系人（名字 + 星标）| 某个发现条目能由联系人的发现密钥认证解开，随后设备证书匹配该联系人 |
| 附近的人（名字 + 色块 + 标签）| 对方是「所有人」模式，与我无关系 |

陌生人可以把自己起名为我联系人的名字，所以「联系人」与「附近的人」在视觉上必须明显不同，且联系人身份只由密钥判定。

## 一次性发送

1. 发送方按连接卡片里的设备公钥拨号；QUIC 握手必须匹配该公钥。双方随后出示设备证书，接收方由此判定关系。
2. 发送方发一条发送请求：条目列表（名字、大小、类型；文字/链接直接内联，上限 64 KiB）、总大小。
3. 接收方决定：
   - 发送方是我的设备 → 自动接收；
   - 发送方是联系人且我对他开了「免确认」→ 自动接收；
   - 否则弹出请求，等待用户点「接收」或「拒绝」（超时 2 分钟视为拒绝）。
4. 接收后按[线路协议](wire.md)传输，逐文件 BLAKE3 校验，落在「收到的」。

## 防滥用

- 每个来源设备同时最多 1 个待确认请求；全局同时最多 5 个；超出直接拒绝并告知发送方「对方忙」。
- 被拒绝的来源 10 分钟冷却。
- 「所有人」模式 10 分钟后自动回到「仅联系人」，界面持续显示剩余时间；它只对本地 IP 链路生效，远程来电照旧按「仅联系人」处理。
- 请求里的名字、文件名在显示前截断与净化（长度、控制字符、Unicode 方向控制符）。
- 一次性发送不创建任何持久关系，不写入联系人。
