# 用户与场景

AA4C 面向**个人、家庭、小团队**。它是人与人之间用的软件：大多数时候，发送的一方和接收的一方是两个人，
而且其中一方很可能还没装 AA4C。

## 场景

按发生频率排序。每个场景写明「谁、在哪、想做什么、现在的替代做法」，后面的功能设计以这些场景为准。

### 1. 身边的人：「把这几张照片给你」

聚会、出游、办公室里，人就在旁边，想把照片、视频、文档给他。可能同一个 WiFi，也可能没有共同路由器但能用
Wi-Fi Direct、临时热点、蓝牙或系统提供的其他近场能力。一次性的，发完就完。
对方常常没装 AA4C，也不想为此注册什么。

- 现在的替代：微信（压缩画质、大文件发不了）、AirDrop（仅限苹果设备）、LocalSend（双方都得装）。
- AA4C 要做到：打开就能看到身边的人，点一下就发；接收方可以安装 AA4C，也可以不安装。没安装时，有本地 IP 链路就扫码在浏览器里收；
  两端系统有可用的系统分享（如 AirDrop、Quick Share、蓝牙发送）时也可直接交给系统发送。可用能力不同就如实显示，不承诺每个平台都有同一种无线方式。

### 2. 自己的手机和电脑：「照片导到电脑上」「这个文件发我手机」

每个人每天都会遇到：手机拍的照片要到电脑上处理，电脑上的文件要带到手机上，顺手发一段文字、一个链接。

- 现在的替代：微信文件传输助手（压缩、有大小限制、绕道服务器）、数据线、网盘。
- AA4C 要做到：自己的设备之间零确认互传；新设备扫一次码加入，以后自动认得。

### 3. 远方的家人朋友：「给爸妈发个视频」「给老同学发个大文件」

不在同一个网络，文件很大，不想上传到网盘再分享链接。

- 现在的替代：网盘（上传下载两遍，限速，要账号）、微信（大小限制）。
- AA4C 要做到：加一次联系人（当面扫码，或发个邀请链接），以后优先直连；直连失败时只经双方可用的自建中转站转发端到端密文。
  不想先加联系人时，可发一次性发送链接；远程接收方必须安装 AA4C。对方没装时，先安装，再在 AA4C 里打开或粘贴这条链接。

### 4. 一家人：「全家的照片汇到一起」

父母、孩子的手机里各有照片，想自动备份到家里的电脑或 NAS，形成一个全家都能看的相册。

- 现在的替代：各家厂商的云相册（要账号、要付费、数据在别人那里）、手动拷贝。
- AA4C 要做到：建一个「我们家」空间，每个人的手机相册自动汇到家里的常开设备；家人都能看，谁可以改由角色决定。

### 5. 小团队：「项目文件夹几个人一起用」

三五个人共用一个项目文件夹，有人只看、有人要改；有人离开团队要能撤掉他的权限。

- 现在的替代：企业网盘、Syncthing（按设备配置，没有「人」和「角色」，对普通人太难）。
- AA4C 要做到：建一个空间，加成员、分角色，共享文件夹在成员的设备间同步。

### 6. 我自己的几台电脑：「家里和单位的电脑连成一片」

家里的台式机、单位的台式机、手机，永远不会同时在一个网络里，但希望它们互相认得、随时能取文件。

- 现在的替代：远程桌面、网盘、Tailscale（要账号）。
- AA4C 要做到：三台设备都是「我的设备」，在任何网络下都能找到彼此（详见[连接阶梯](../network/ladder.md)）。

### 7. 动手能力强的人和 AI agent

在 NAS 或服务器上无界面运行 AA4C；写脚本自动发文件；让 AI agent 帮忙「把这份报告发到我手机上」。

- AA4C 要做到：一个无界面程序 `aa4c`，命令行与 MCP 能驱动全部功能（信任相关的除外，见 [MCP 与 AI agent](../surfaces/agents.md)）。

## 不是我们的用户场景

- 公开分发文件给不认识的人（资源站、网盘外链、社区）。
- 企业级的权限审计、单点登录、集中管理。
- 下载网上的资源（HTTP/BT 下载器）。
- 像网盘一样让远方的人不装 App、发送设备离线后仍能从浏览器下载；这需要中心存储或额外网关，不在当前承诺内。
