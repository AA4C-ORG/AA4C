# 从第一代学到的

第一代（v0.1–v0.8）用事故换来的教训。每一条在第二代里都要变成一个测试、一条规则或一段文档，不能只停留在记忆里。

## 协议与网络

| 教训 | 第二代的落点 |
|---|---|
| 会话最后一条消息（`TaskDone`）写完就丢弃 QUIC 连接，排队中的数据被连同连接一起冲掉；接收方文件已完整落盘却记为失败 | 协议规定：最后一条消息后先半关闭写端、等对方关闭再丢弃（[线路协议](network/wire.md)）；多设备测试覆盖 |
| QUIC 空闲超时 8 秒，在负载高的共享机器上误杀连接 | 空闲超时明显长于任何应用层等待；测试台在 CPU 压力下也要跑 |
| Windows 默认 `IPV6_V6ONLY` 开着，只绑 `[::]` 会让 IPv4 整个失联 | 双栈监听显式关闭 `IPV6_V6ONLY`；Windows CI 覆盖 |
| 「探测空闲端口再释放、再让别人去绑」有竞态，可能连到别人的进程 | 端口由自己直接绑定并持有，不先探测再交出 |
| 端口映射会改用户路由器的配置 | 两道闸（远程连接 + 端口映射）；退出时拆除；自动化测试只用假后端 |
| 允许未配对设备发起请求后，打破了「对端必然是已知设备」的隐含假设，外键约束把连接在中途悄悄挂断 | 关系判定显式化：每条请求先判定「我的设备 / 联系人 / 成员 / 陌生人」，代码里不隐含假设 |
| 引荐落库若用通用的「插入或更新」，会把已有的信任关系打回未配对；「忽略」若删记录，下一轮又会被加回来 | 第二代用签名证书与签名吊销，从结构上消除；吊销不可撤回 |
| 发送方内部取消时没有通知对端，对端一直等到超时 | 协议规定明确取消必须发 `cancel`；网络中断才保留续传文件 |
| mDNS 每个实例一条线程加一组 5353 socket，多实例测试互相挤 | 自写信标；测试台默认用进程内发现 |
| 后台循环在关停时没停掉，测试与重启时泄漏 | 引擎关停有统一的取消信号，测试验证关停后端口与线程都已释放 |

## 存储

| 教训 | 第二代的落点 |
|---|---|
| 迁移脚本重建表时，外键级联删光了子表数据——会波及全部老用户升级 | 不用 SQLite；数据格式升级用 Rust 写，每一步都有「旧数据 → 新数据」测试，升级前自动备份 |

## 测试与 CI

| 教训 | 第二代的落点 |
|---|---|
| CI 两次红了一周、一个月没人发现，期间的问题层层叠加 | CI 红了当场修；每阶段合入后等 CI 出结果再继续 |
| 挂着 `continue-on-error` 的任务坏了没人知道 | 这类任务必须有人定期看，或者不用 |
| 测试用固定循环次数等待事件，不匹配的事件白白吃掉配额 | 一律用墙钟预算 |
| `curl --retry` 不重试证书类错误 | `--retry 5 --retry-all-errors` |
| 测试找不到环境变量时显式 panic，看起来和真失败一样，被当成「环境问题」放过 | 依赖外部环境的测试单独分组，缺环境时明确跳过并在 CI 摘要中显示 |
| 依赖公告（rustls 等）只在推送后才被 CI 发现 | 依赖审计定期运行（不只在推送时）|
| 一条「私有 CSS < 500 行」的指标量错了东西，真正的问题是重复 | 指标要量真正关心的东西，写成能 grep 的判据 |

## 界面与文档

| 教训 | 第二代的落点 |
|---|---|
| 连续七个版本没人真正看过一眼界面 | 界面改动必须附离屏截图 |
| 首页是「能力宫格」，链到侧栏已有的入口——菜单的菜单 | 首页回答一个问题：我能发给谁、我的设备连上了没有 |
| 文档反复声称已经不成立的状态（「设计稿，未实现」挂在已发布的功能上）；HANDOFF 长到 115 KB | 进度放 Issues，决定放 ADR，书只写当前设计；不写交接文档 |
| 打包失败的报错语焉不详，先猜了两个「看起来合理」的原因都不对 | 构建失败先开详细输出看真实原因，不连续猜测 |

## Android

| 教训 | 第二代的落点 |
|---|---|
| 局域网组播需要持有 `MulticastLock` | 薄壳在引擎运行期间持有，并有冒烟测试 |
| `compileSdk 36` 与 build-tools 35/36 必须手动预装；经代理下载 SDK 常在中途截断 | 写进构建文档；CI 缓存 SDK |
