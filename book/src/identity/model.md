# 人 · 设备 · 联系人 · 空间

> 决定见 [ADR 0002](../../../docs/adr/0002-person-device-contact-space.md)。本章是设计细节，
> 标有「⚠ 待定」的地方列在[待细化的问题](../open-questions.md)。

## 为什么需要「人」

第一代只有设备：信任是一台设备对另一台设备的关系。这在「一个人的几台设备」里还凑合，一到人与人之间就崩了：

| 想做的事 | 只有设备时 | 有了「人」之后 |
|---|---|---|
| 加一个朋友 | 他的手机、电脑、平板分别配对三次 | 加一次，认得他所有设备 |
| 他换了新手机 | 再配对一次 | 他自己把新手机加进「他」，我这边自动认得 |
| 家里人共享相册 | 无法表达「家里人」 | 建一个空间，成员是人 |
| 家里电脑和单位电脑互认 | 手机作「引荐」，两边逐台确认 | 两台都由我的个人密钥签名，自动互认 |

## 四个概念

```text
人（Person）                   一把个人密钥（Ed25519）
 ├─ 设备证书：设备 A ──签名──   「设备 A 是我的」
 ├─ 设备证书：设备 B
 └─ 吊销：设备 C               「设备 C 不再是我的」

联系人（Contact）              我存下的别人的个人公钥（+ 备注名 + 双方的发现密钥）

空间（Space）                  id + 名字 + 成员表（人 + 角色）+ 共享文件夹
                               成员表的每个版本由所有者签名
```

### 人与个人密钥

- 第一次打开 AA4C 时生成：一把**个人密钥**（代表我这个人）和一把**设备密钥**（代表这台设备），并用个人密钥给这台设备签第一张设备证书。
- 人的唯一标识是个人公钥的**指纹**（BLAKE3）。**名字**是自报的，不唯一、可伪造，只用于显示。
- 个人私钥**保存在我的每一台设备上**（加入新设备时经加密通道复制过去），存在系统提供的安全存储里
  （macOS/iOS 钥匙串、Android Keystore 包装、Windows DPAPI、Linux Secret Service，不可用时退回文件 + 权限 0600）。

### 设备与设备证书

- 每台设备有自己的**设备密钥**，私钥永不离开这台设备。网络握手用的就是它（[线路协议](../network/wire.md)）。
- **设备证书**：个人密钥对以下内容的签名——设备公钥、设备名、平台、签发时间、证书格式版本。
- 连接时，设备出示「设备公钥 + 设备证书」；对方验证签名，就知道「这是某某人的设备」。
- 证书没有过期时间：设备一直有效，直到被吊销。

### 吊销

- 「移除这台设备」= 用个人密钥签一条**吊销**：「设备 X 自某时起不再是我的」。
- 吊销会同步给我的所有设备和所有联系人（每次连接时交换吊销列表）。吊销不可撤回；同一台设备想回来，要重新加入、换新设备密钥。
- 这正是第一代刻意避免自动引荐的原因之一（Syncthing 的「删了又被加回来」）在这里不成立：吊销是签名的事实，不是一条可被覆盖的记录。

### 联系人

- 联系人 = 别人的个人公钥 + 我给的备注名 + 经认证流程交换的发现密钥 + 我对他的设置（是否免确认接收、是否可经我的中转站中转等）。
- 因为存的是个人公钥，他的任何一台持有有效设备证书、未被吊销的设备连过来，我都认得。
- 发现密钥只让默认信标对联系人可识别，不代表信任提升；真正连接仍须验证设备证书与吊销状态。
- 联系关系是**单向存储、双向建立**的：添加流程里双方各存对方一次；任意一方删除，只影响他自己那边。

### 空间

- 空间 = 随机 id + 名字 + **成员表** + 共享文件夹列表。
- 角色：**所有者**（管成员和角色，可以有多个 ⚠ 待定）、**可编辑**（可以往共享文件夹里加、改、删）、**只读**（只接收）。
- 成员表是一条**签名链**：每个新版本包含上一版本的摘要和所有者的签名。成员的设备只接受能接到链上、签名有效的版本。
- 加入空间的前提是对方已经是**某位所有者的联系人**（所有者用联系人身份邀请他）。
- 共享文件夹的同步只在「当前成员表里、角色允许」的人的设备之间进行。

## 关系一览

| 关系 | 能做什么 | 怎么建立 | 怎么解除 |
|---|---|---|---|
| 我的设备 | 一切：零确认互传、浏览与取回、远程管理、同步我的所有空间 | 新设备加入流程（扫码 / 核对码）| 吊销 |
| 联系人 | 互相发送（可免确认）、出现在「发给谁」、可加入空间、可选用我的中转站 | 当面扫码 / 邀请链接 | 删除联系人（单方）|
| 空间成员 | 按角色同步共享文件夹 | 所有者邀请（须为联系人）| 所有者移除 / 自己退出 |
| 附近的人 | 给我发一次，我确认后接收 | 无需建立 | — |
| 持有一次性发送链接的人 | 收那一份东西 | 我生成链接 | 我撤销 / 到期 |

## 必须如实告诉用户的代价

1. **任何一台设备失守，等于「我」失守**：它持有个人私钥，能签新设备、能吊销我的其他设备。
   应对方案是首要待定问题（⚠ 设备失窃，见[待细化的问题](../open-questions.md)第 1 条）。
2. **没有账号就没有找回**：所有设备都丢了，个人身份就没了；联系人需要重新加，空间需要重新被邀请。
   提供可选的**恢复码**导出（⚠ 格式与是否强制提醒待定）。
3. **移除成员收不回已同步的文件**：只能保证此后不再同步给他。
4. **名字可以伪造**：只有指纹可靠。附近的人列表里，陌生人可以把自己起名为你的联系人的名字——
   所以联系人与陌生人在界面上必须有视觉区分（联系人有星标/头像，陌生人只有名字 + 色块 + 「附近的人」标签）。

## 与第一代概念的对应

| 第一代 | 第二代 |
|---|---|
| 完全信任设备 | 我的设备 |
| 朋友（设备级）| 联系人（人级）|
| 临时 / 陌生 | 附近的人（一次性发送）|
| 配对（PIN）| 加入我的设备 / 添加联系人（核对码）|
| 引荐 + 逐台确认 | 设备证书（自动）|
| 同步范围（仅自己的设备）| 共享文件夹（属于空间，可多人）|
