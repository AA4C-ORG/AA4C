# 桌面版

Windows、macOS、Linux。绝大多数用户使用的形态。

## 技术

- 界面用 Rust：**egui** 或 **Slint**，由 M0 的两个原型决定（[路线图](../roadmap.md)）。评判标准：
  中文输入法、中日韩字体（打包子集或回落系统字体）、托盘、系统通知、拖放、无障碍、普通人眼里的观感、依赖数。
- 引擎在桌面进程内运行，同时开本地 IPC，让 `aa4c` 命令行与 AI agent 能操作正在运行的桌面版。
- 界面是**瘦**的：每个按钮都调一个命令；界面状态可序列化，便于离屏截图验证与自动化检查。

## 常驻与系统集成

- 关闭窗口不退出，驻留托盘/菜单栏；托盘菜单：打开、接收模式切换（含「所有人 · 10 分钟」）、退出。
- 开机自启（默认开，可关）。
- 系统通知：收到请求、传输完成、远程发送失败及原因。
- 拖放：把文件拖到窗口或托盘图标上即可选择接收人。
- 系统「分享」菜单接入（macOS 共享扩展、Windows 共享目标）为 v1 之后的增强。
- 当面发送页调用 `proximity.routes`：桌面系统公开本地建链或文件交付能力时才显示；Linux 发行版或桌面环境没有稳定接口时明确不支持，
  不用未经维护的无线依赖凑出一个按钮。系统直传仍要人在系统选择器里确认。

## 信息架构

主导航四项（延续第一代 V0.8 收敛后的结论，按第二代模型调整）：

| 页面 | 回答的问题 |
|---|---|
| **首页（附近与联系人）** | 我能发给谁？身边有谁、联系人谁在线、我的设备连上了没有、走的哪一档 |
| **收到的** | 别人发来了什么？待确认的请求、已收到的文件与文字 |
| **空间** | 我在哪些空间里？共享文件夹、成员、同步状态 |
| **设置** | 我的名字、接收模式、保存位置、远程连接、中转站、我的设备、联系人管理、插件 |

发送不是一个页面而是一个动作：在首页选中人或设备 → 选文件/输入文字 → 发送；或先拖文件进来再选人。

## 设备与连接的可见性

首页对「我的设备」显示连接状态与档位（「已连接 · 本地直连」「已连接 · 经中转站（较慢）」「找不到——上次 3 小时前在家里的网络」），
连不上时直接给出原因和可做的事（[连接阶梯](../network/ladder.md)「连不上时」一节）。
开放了服务的设备旁边直接给出「SSH」「远程桌面」入口（[远程访问](../network/remote-access.md)）。这是 AA4C 不可替代能力在界面上的落点。

## 验证

界面改动必须附离屏截图（不弹窗口、不抢焦点）；并有自动化检查：「界面上每个可点击动作都能在 `aa4c commands` 里找到对应命令」。
