# 安全与威胁模型

漏洞报告方式见仓库根目录 `SECURITY.md`（dev@aa4c.com）。本章是设计层面的威胁模型，**区分「已设计」与「待定」**，
不把计划写成已实现。

## 要保护什么

| 资产 | 说明 |
|---|---|
| 文件内容 | 传输中的、共享文件夹里的 |
| 个人私钥 | 等于「我」：能签设备、能吊销 |
| 关系图 | 谁是谁的联系人、谁在哪个空间 |
| 元数据 | 谁在什么时候给谁发了什么文件名、多大 |
| 设备可用性 | 不被刷屏、不被拖垮带宽 |

## 对手与对策

| 对手 | 能做什么 | 对策 | 状态 |
|---|---|---|---|
| 同一本地 IP 链路的窃听者 | 抓包 | AA4C 直连使用 QUIC/TLS 1.3 端到端加密；双方用设备公钥认证 | 已设计 |
| 同一本地 IP 链路的陌生人 | 冒充联系人的名字；刷屏发请求 | 联系人只由密钥判定、界面视觉区分；默认仅联系人；限速与冷却 | 已设计 |
| 同一本地 IP 链路的观察者 | 凭默认信标认出设备主人，或跨网络跟踪同一设备 | 默认信标载荷不含公开稳定身份、条目数按档位填充，联系人用发现密钥识别；临时「所有人」模式才公开（同一网络内靠 IP/MAC 关联不在此列）| 已验证（M0 实验） |
| 同一本地 IP 链路的陌生人 | 截获扫码收发页的内容 | 随机口令防猜测；**明文 HTTP 无法防抓包**，界面提示 | ⚠ 残余风险 |
| 恶意或误选的系统直传设备 | 收到交给操作系统的文件；系统只报告「已提交」 | 必须人在场选择并确认；界面明确这不是 AA4C 加密直连；不把「已提交」写成「对方已收到」 | ⚠ 安全性与状态受平台约束 |
| 恶意联系人 | 发恶意文件；滥用我的社交中转 | 收到可执行文件时提示；社交中转默认关、可限额、可按人撤销 | 已设计 |
| 中转站运营者（自建的，或联系人的）| 看流量、记录谁连了谁 | 端到端加密，中转站看不到内容与文件名；能看到连接时间、地址、字节数 | 已设计（元数据泄露为已知限制）|
| 截获邀请链接的人 | 抢先使用邀请加 A 为联系人 | 一次性口令；A 确认时显示名字与核对码 | ⚠ 是否强制核对待定 |
| 偷走 / 捡到我设备的人 | 拿到个人私钥：冒充我、签新设备、抢先吊销我的其他设备 | 设备锁屏 + 系统安全存储；从其他设备吊销 | ⚠ **首要待定问题** |
| 拿到我某台设备的人（远程访问开启后）| 经端口转发连到我其他设备开放的 SSH、远程桌面 | 开放服务是 trust、默认不开；转发不替代服务自己的认证；吊销即断开 | 已设计 |
| 恶意插件 | 读文件、联网、卡死或击穿宿主解析器 | wasmi 零导入、fuel/内存/栈上限、受限意图、panic 回归样本；必要时隔离进程 | 已设计，依赖实现待验证 |
| 被提示注入的 AI agent | 替用户改信任；把获准目录里的文件发错人 | `trust` 默认不暴露；默认只能发给我的设备，联系人需显式授予；文件根与字节预算；核对码只能人比对 | 已设计 |
| 截获一次性发送链接的人 | 在过期前抢先接收 | 256 位 bearer 口令、摘要落库、一次成功即失效、可撤销；创建页提示不要公开转发 | 已设计 |
| 网络上的观察者 | 看到两台设备在通信、流量大小 | 不在范围内（不做流量混淆）| 不防 |

## 不在范围内

- 设备操作系统已被攻破（恶意软件、root/越狱后被植入）。
- 用户不核对核对码就确认了一个他并不认识的人。
- 流量分析。
- 物理接触到已解锁的设备。
- 授予目录内指向目录外 inode 的硬链接：路径沙箱认不出硬链接，它在文件系统意义上就是授权目录里的文件（[ADR 0020](../../docs/adr/0020-cap-std-for-granted-roots.md)）。

## 默认值

- 接收模式默认「仅联系人」；「所有人」最长 10 分钟，且只对本地 IP 链路生效。
- 远程访问默认不开放任何服务；端口转发只监听 `127.0.0.1`。
- 远程连接默认开（跨网是核心功能），端口映射在远程连接开时默认开；中转站默认关；社交中转默认关。
- 信任相关设置不放 `config.toml`，只能经 `trust` 级命令修改。

## 硬性工程要求

- 一切来自网络、文件、参数、插件输出的数据都是敌意输入：长度与计数有上限、用 checked 运算、按上限分配内存。
- 路径净化：拒绝 `..`、绝对路径、Windows 盘符与保留设备名、分隔符变体、控制字符与 Unicode 方向控制符。
  Agent/插件根目录用预打开目录句柄约束；只做 canonicalize 再 open 会有符号链接替换竞态，不算授权实现。
- 日志里不写私钥、完整公钥、文件内容、口令。无界面设备首次启动的加入码只打到标准输出、5 分钟过期，且必须配合核对码比对。
- 默认信标不得出现名字、个人/设备公钥、真实条目数或其他跨轮换周期稳定的公开标识；抓包隐私测试进入 M0。
- 协议解码器、路径净化、插件 manifest 解析、证书解析纳入 fuzz。
- 依赖审计（`cargo audit` / `cargo deny`）在 CI 里运行，公告出现即处理。

## 上限（v1 初值，可调）

| 项 | 上限 |
|---|---|
| 单条控制消息 | 1 MiB |
| 一次发送的条目数 | 10 000 |
| 内联文字 | 64 KiB |
| 每个来源的待确认请求 | 1 |
| 全局待确认请求 | 5 |
| 拒绝后的冷却 | 10 分钟 |
| 本地 IPC 单条消息 | 1 MiB |
| MCP 批量步数 | 256 |
| MCP 发送目标 | 默认是我的设备；联系人需启动时显式授予 |
| 插件内存 | 64 MiB |
