# 0006 redb + config.toml 代替 SQLite

状态：提议中（2026-10-29）

第一代用 rusqlite 的 bundled 模式，等于把 SQLite 的 C 源码编进每个构建；数据库文件对人和 agent 都不透明，13 个迁移脚本
还藏过「重建表时顺着外键级联删光子表」这种会波及全部老用户的 bug。

决定：**状态**（设备、联系人、空间、索引、传输记录、分享）放 redb（纯 Rust、ACID 的嵌入式键值库）；
**配置**放数据目录下的 `config.toml`，人和 agent 都能直接读改，引擎启动时校验。数据格式版本记在 redb 的元数据表里，
升级逻辑在 Rust 里写并配测试。

考虑过的方案：继续用 SQLite（成熟、能写 SQL 排查）——但违背「尽量只用 Rust」；排查需求由 `aa4c` 的只读命令满足。
fjall 是另一个纯 Rust 候选，M0 时一并比较依赖与稳定性后定案。
