# 0002 人 · 设备 · 联系人 · 空间，不要账号

状态：已接受（2026-10-29）。细节设计见 [book/src/identity/model.md](../../book/src/identity/model.md)。

第一代的信任按**设备**算：加一个朋友要把他每台设备分别配对；朋友、家人、同事都归成同一档「朋友」，而「朋友」不能同步，
所以愿景里排在前面的「家庭相册」「团队共享文件夹」在模型里根本不存在。自己的两台设备不在同一网络时只能靠「引荐 + 逐台确认」。

决定：引入四个概念，仍然**不要账号、不要服务器**：

- **人**：一把个人密钥（Ed25519）。
- **设备**：每台设备一把设备密钥，由主人的个人密钥签一张设备证书「这是我的设备」。
- **联系人**：我加过的人，存他的个人公钥，因此认得他所有未被吊销的设备。
- **空间**：一组人 + 角色 + 共享文件夹；成员变更由所有者签名。

个人密钥签名是**密码学陈述，不是转述**：只有持有我个人私钥的设备能签出「这是我的设备」，传递范围天然受限；移除设备是签名的吊销，
不会被别处加回来。Syncthing introducer 的两个已知问题（信任失控扩散、删了又被加回来）在结构上不存在，第一代的「引荐」因此取消。

后果：个人私钥存在我的每台设备上，任何一台失守都等于身份失守；没有账号就没有找回，需要可选的恢复码；
从空间移除的成员已经同步走的副本仍在他手里。这三点必须写进安全文档和界面提示。设备失窃后的应对是首要待细化问题
（[open-questions.md](../../book/src/open-questions.md)）。
