# 0011 信任变更只能由人完成

状态：已接受（2026-10-29）

AA4C 要对 AI agent 友好：命令行和 MCP 能驱动全部功能。但 agent 读到的网页、文件、消息里可能藏着提示注入；
一次注入如果能让 agent 替用户「添加联系人」或「把某人加进家庭空间」，后果是长期的、难以察觉的。

决定：每个命令带**静态能力级别**：`read`（只看）、`act`（做事，如发送、取回）、`trust`（改变谁被信任或谁能接近我：加入我的设备、添加/删除联系人、
改空间成员与角色、吊销设备、接收陌生人的内容、打开「所有人」接收、开关社交中转、安装插件）。一个行为在不同关系下需要不同级别时，
拆成不同命令，不在运行时偷偷提升级别。**MCP 默认只暴露 read 与 act**；`trust` 级需启动时显式加 `--allow-trust`，
且即便打开，需要人眼比对核对码或系统级用户验证的步骤，agent 也无法代替完成。每次调用还带服务端生成的 `CallerContext`；
MCP 会话的文件访问限定在启动时授予的读写目录内；发送还限定接收目标与字节预算，一次性链接创建需单独授权。
插件只能获得安装时批准的 read/act 子集，永远没有 trust。
