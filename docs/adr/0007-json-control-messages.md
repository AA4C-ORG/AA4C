# 0007 线路控制消息用 JSON

状态：已接受（2026-10-29）

第一代的线路消息用 bincode 1 编码：按位置编码，加字段会让旧版本解码失败，于是只能「只许追加变体」，每次协议演进都要提一个版本号、
写一个门槛；bincode 1 也已无人维护。

决定：控制消息是**长度前缀的 JSON**（4 字节大端长度 + UTF-8 JSON，单条上限 1 MiB）；文件内容是控制消息之后的**裸字节**。
新增字段一律可选（`serde(default)`），未知字段忽略，未知消息类型回一个 `unsupported` 错误。协议版本只在不兼容时才提升。

理由：控制消息很小，JSON 的体积代价可以忽略；向前兼容变成默认行为；抓下来的协议记录人和 agent 都能直接读。
