# 0017 远程访问用服务转发，不做插件、不做虚拟网卡

状态：提议中（2026-10-30）。设计见 [book/src/network/remote-access.md](../../book/src/network/remote-access.md)。

SubnetDesk 这类局域网远程桌面要求两端先网络互通，跨网只能另装 VPN；而 AA4C 已有的「我的设备」身份与连接阶梯，正好是它们缺的那一半。
用户希望在 AA4C 之上得到一个简单的 Tailscale：任何网络下 SSH 到自己的 NAS、远程控制自己的电脑。

决定：v1.0 增加**服务转发**。一台设备把本机的 TCP 服务开放给「我的其他设备」，后者在本机 `127.0.0.1` 得到一个端口，
连接沿现有的端到端 QUIC 与连接阶梯转发。SSH 与远程桌面的认证、画面和输入仍由 sshd、SubnetDesk 或系统自带的远程桌面负责；
AA4C 只解决「连得上」，不解决「让不让进」。

- **不做成插件**：插件零导入、不能联网（ADR 0008），而转发要长期持有网络连接与本机 socket。
- **不在引擎里做远程桌面**：截屏、输入注入与音视频编解码带来平台 C/C++ 依赖（SubnetDesk 用 libvpx、aom、opus、libyuv），
  远超依赖预算；SubnetDesk 是 AGPL-3.0，只以独立进程、经命令注册表配合，不并入 AA4C 的代码。
- **不做虚拟网卡**：TUN 驱动、管理员权限、手机上唯一的 VPN 位置与 iOS Network Extension 权限都与「轻」相悖；
  按端口转发已覆盖个人用户的主要需求。
- 第一版只在我的设备之间、只转 TCP。开放服务是 `trust` 级操作，目标地址默认只能是回环地址。

考虑过的方案：Wasm 插件（做不到）；把 SubnetDesk 并入桌面版（依赖与许可证都不允许）；像 Tailscale 那样的完整三层覆盖网络（太重）。

后果：AA4C 从「传文件」扩展到「让我的设备彼此连得上」。产品边界（ADR 0009）不变；它进入 v1.0 的 P1 范围，排在路线图 M6，不新增连接层与依赖；
本 ADR 接受时，README 与 AGENTS.md 的一句话定位要同步修改。
