# 0015 默认信标不暴露稳定身份

状态：提议中，待 M0 实验证实（2026-10-30）

原设计在「仅联系人」模式下轮换人的标记，却仍在每个信标里广播稳定的设备公钥并用设备私钥公开签名。
旁观者不需要知道人的公钥，也能用稳定设备公钥长期跟踪同一台设备；轮换标记因此没有达到设计目标。

决定（待实验）：默认的「仅联系人」信标不出现名字、个人公钥、设备公钥或任何公开可验证的稳定标识。
添加联系人时，双方经已认证通道交换随机的 256 位**发现密钥**；我的设备另共享一把自己的发现密钥。
信标用发现密钥生成随时间与随机数变化的标签，并加密最小连接卡片。接收方只尝试自己的联系人密钥；
陌生旁观者不能从信标载荷识别这是谁，也不能凭载荷把同一台设备在不同网络、不同轮换周期之间关联起来；
条目数按固定档位填充，不暴露联系人数。同一网络内靠 IP / MAC 关联设备不在信标能解决的范围内。「关闭」模式只发送我的设备能识别的条目。

「所有人」模式是用户最长 10 分钟的显式选择，只在本地 IP 链路上发送带设备公钥和签名的公开卡片；界面必须持续显示剩余时间。

M0 实验必须确定帧格式、AEAD、轮换周期与填充档位，并验证：信标载荷中没有稳定标识（包括真实条目数）；旧包不能重放；联系人多时信标大小与发现延迟有上限；
删除联系人后不再生成对方可识别的条目。实验通过前，不把当前伪代码当作协议承诺。
