# 0015 默认信标不暴露稳定身份

状态：已接受，附实验定下的帧格式（2026-10-30）

原设计在「仅联系人」模式下轮换人的标记，却仍在每个信标里广播稳定的设备公钥并用设备私钥公开签名。
旁观者不需要知道人的公钥，也能用稳定设备公钥长期跟踪同一台设备；轮换标记因此没有达到设计目标。

决定：默认的「仅联系人」信标不出现名字、个人公钥、设备公钥或任何公开可验证的稳定标识。
添加联系人时，双方经已认证通道交换随机的 256 位**发现密钥**；我的设备另共享一把自己的发现密钥。
信标用发现密钥生成随时间与随机数变化的标签，并加密最小连接卡片。接收方只尝试自己的联系人密钥；
陌生旁观者不能从信标载荷识别这是谁，也不能凭载荷把同一台设备在不同网络、不同轮换周期之间关联起来；
条目数按固定档位填充，不暴露联系人数。同一网络内靠 IP / MAC 关联设备不在信标能解决的范围内。「关闭」模式只发送我的设备能识别的条目。

「所有人」模式是用户最长 10 分钟的显式选择，只在本地 IP 链路上发送带设备公钥和签名的公开卡片；界面必须持续显示剩余时间。

## 实验结果

`experiments/beacon` 定下并验证了下面的格式（14 个测试；`cargo run --release -p beacon-exp --example measure` 复现数字）。

**数据报**（固定 1121 字节，不依赖 IP 分片，低于 IPv6 最小 MTU 的 1232）：

```text
头（明文，29 B）  版本 1 B │ 时间窗口 4 B │ 随机数 24 B
槽 × 13（每槽 84 B）  标签 4 B │ AEAD 密文（卡片 64 B）│ 认证标签 16 B
```

- **AEAD**：XChaCha20-Poly1305，24 字节随机 nonce，头作为附加认证数据；密钥与标签密钥分别由发现密钥经 BLAKE3 `derive_key` 派生。
- **标签**：`BLAKE3 密钥哈希(标签密钥, 窗口‖随机数)` 的前 4 字节。它只用于让接收方先筛一遍再试解密：100 把密钥时一个邻居一个周期的接收成本
  86 µs，对照“每个槽每把密钥都试解密”的 2312 µs，约 27 倍；成本随密钥数线性增长，500 把密钥 261 µs 对 11.6 ms。
- **卡片**（64 B）：设备公钥 32 + 端口 2 + 设备证书摘要 16 + 保留 14。名字等展示信息不进信标，握手后从设备证书和联系人记录取得。
- **槽**：给每个联系人（及我的设备）一个槽，其余是随机填充，槽位在周期内打乱；填充槽与真实槽在字节层面都是均匀随机。
- **档位**：每个周期的数据报数取 1 / 2 / 4 / 8 / 16，旁观者只能看到档位，对应 ≤13、≤26、≤52、≤104、≤208 个条目。
  100 个联系人是 8 个数据报 8968 字节，周期 2 秒时约 4.5 KB/s。超过 208 个条目时用游标轮转，300 个联系人 2 个周期全部覆盖。
- **时间窗口与重放**：窗口 30 秒，接收方接受当前窗口及前后各一个，超出为 `Stale`；解开过的 `(窗口, 随机数)` 记入缓存，同窗口重放为 `Replay`；
  只为真正解开的数据报记录，灌入随机数据报撑不大缓存。窗口不是轮换周期：每个数据报的随机数都是新的，不依赖轮换来防关联。
- **发现延迟**（周期 2 秒，数据报在周期内均匀发出，蒙特卡洛）：无丢包最坏 2 秒；丢包 10% 时中位 1.1 秒、p99 4.0 秒；丢包 30% 时 p99 7.9 秒。
  联系人超过 208 个时再乘以覆盖所需的周期数。
- **依赖**：blake3（`pure` 特性，无 C/汇编）、chacha20poly1305、getrandom，共 22 个唯一 crate，全部纯 Rust。

**已验证的性质**：同一设备在不同窗口的两组数据报之间没有共同的 8 字节子串，也没有同偏移的 4 字节连续相同；数据报长度与真实联系人数无关；
没有匹配密钥时一律返回空结果，“没有联系人”和“密钥不对”无法区分；删除联系人后（任一方）不再产生可识别的条目；任何单字节篡改都不会产生伪造的卡片；
畸形与截断输入返回错误；设备忽略自己的信标；最大数据报经真实 UDP 套接字往返无损。

**已知边界**：
- 档位本身可见，同一 IP 发出的数据报能被归为一个周期；同一网络内靠 IP / MAC 关联不在范围内。
- 在窗口内（最长约 90 秒）把抓到的数据报转发到别处，接收方会看到“该设备在这个地址”，但拨号时 QUIC 握手校验设备公钥，冒充者签不出，最多是一次失败的拨号。
- 联系人本人持有发现密钥，所以他能在任何网络里认出我的信标；这是“联系人互相发现”的本意。
- **发现密钥的内存擦除尚未实现**（删除联系人只是不再使用该密钥）；实现 `aa4c-state` 时随安全存储一起做，并补测试。
